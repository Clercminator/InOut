## Analytics and public-site limits

Android has an existing Firebase Analytics/Crashlytics transport, with `GOOGLE_SERVICES_JSON` present as a file variable in both EAS preview and production. Collection defaults off and requires the saved telemetry opt-in. Local exports intentionally lack that private file, so their effective `firebasePlatforms` values are false; cloud build/native artifact evidence must establish Android inclusion. No `GOOGLE_SERVICES_PLIST` is configured for iOS, and the browser `AnalyticsService` has no sink. No provider was added.

Event contracts/call sites cover onboarding, sessions, Daily Reset, fitness results/bests, Coach, sharing, verified purchases, eligible ad SDK impressions, notifications and runtime errors. Properties exclude notes, ratings and local identifiers; failures cannot block practice. First-open is claimed only after transport initialization succeeds, with a retry regression test. Pre-consent events are deliberately dropped; first-open represents first consented use. Delivery failures are best-effort, with no durable retry queue. Acquisition-source values are allowed but no campaign attribution/reporting flow is configured. Native consented event receipt, cohorts and dashboards have not been verified: **Day-1/Day-7 retention and acquisition funnels are not accepted production capabilities**. Required work/evidence: owner decision/disclosures, Android Firebase event receipt and reports, an authorized iOS Firebase app/plist if desired, and separately approved consent/transport/attribution work for browser conversion measurement.
