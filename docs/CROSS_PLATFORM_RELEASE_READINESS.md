## Release blockers and required evidence

1. Apple Developer organization enrollment is processing. App Store Connect, paid-app agreements, Apple signing credentials, TestFlight and sandbox purchase tests are not available yet.
2. All seven gates in `release/readiness.json` are false and store metadata is a draft. The `production` profile is deliberately blocked by the existing release policy until those gates and approved metadata are in place.
3. The EAS production environment must contain the matching public iOS RevenueCat SDK key (`EXPO_PUBLIC_REVENUECAT_IOS_KEY`, prefix `appl_`). The app-side `.env.example` is intentionally blank. Verify the EAS environment without putting Apple private keys or RevenueCat secret keys in source or `EXPO_PUBLIC_*` variables.
4. Configure the existing App Store products and RevenueCat mapping without changing the identifiers, entitlement, offering or prices. Then verify purchase, cancel, pending, expiry, restore and subscription-management paths using Apple sandbox/TestFlight.
5. Verify UMP consent and privacy-options behavior in applicable regions, test ads/no-fill and suppression on device, and complete both store privacy declarations. Decide ATT from actual tracking configuration, not from the presence of an ad SDK alone.
6. Inspect the EAS-generated `.ipa` for the app and all embedded SDK privacy manifests and required-reason API declarations. No local Xcode build or signed iOS artifact was produced in this task.
7. Decide whether iOS Universal Links are required. If so, set the verified Apple Team ID in `release/links.json`, complete the site association file for `inout.imrtech.xyz`, and verify install/open/fallback behavior. Do not enter a guessed Team ID.
8. Complete TestFlight device acceptance: fresh install and upgrade, account-free offline practice, purchases/restores, consent, notifications and actions, interruptions/headphones/silent switch, sharing, safe areas, Dynamic Type, VoiceOver and all supported locales.
